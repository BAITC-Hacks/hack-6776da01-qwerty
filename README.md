# HackAlem AI

Локальный прототип системы автопротоколирования совещаний.

## Возможности

- принимает MP3, WAV, M4A или MP4;
- локально распознаёт речь через Faster Whisper;
- автоматически определяет язык (русский/казахский/смешанная речь);
- показывает транскрипт с временными метками;
- назначает локальные метки говорящих `SPEAKER_00`, `SPEAKER_01`;
- использует обращения по имени для подписи следующей реплики;
- сохраняет локальные голосовые профили и использует их на следующих совещаниях;
- выделяет потенциальные поручения, ответственных и сроки;
- формирует саммари;
- экспортирует результат в DOCX, PDF и JSON;
- позволяет проверить и изменить статус поручений перед экспортом.
- позволяет вручную сопоставить `SPEAKER_00`/`SPEAKER_01` с ФИО и исправить поручение перед экспортом;
- показывает оценку качества протокола и предупреждения о слабой диаризации.

Аудио и текст не отправляются во внешние облачные API. При первом запуске
скачивается локальная модель распознавания в каталог `models/`.

## Запуск на Windows

```bat
py -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
streamlit run app\main.py
```

Откройте адрес из терминала, загрузите аудиозапись и нажмите «Создать протокол».

### Опциональный умный анализ

Для более глубокого извлечения поручений можно установить Ollama и локальную модель:

```bat
ollama pull qwen2.5:7b
```

После запуска Ollama включите в боковой панели переключатель «Умный локальный анализ». Если локальная модель недоступна, приложение автоматически использует встроенный анализатор. Аудио и транскрипт не отправляются во внешний API.

## Демонстрационный сценарий

1. Загрузить тестовую запись совещания.
2. Дождаться локальной расшифровки речи.
3. На вкладке «Результат» проверить саммари и поручения.
4. При необходимости изменить статус поручения: «Не проверено», «В работе», «Выполнено» или «Просрочено».
5. При необходимости ввести в поле имена говорящих в формате `SPEAKER_00=ФИО`.
6. На вкладке «Экспорт» скачать DOCX, PDF или JSON для интеграции с СЭД и дашбордом.

Приложение реализовано как локальный веб-интерфейс. Такой формат подходит для закрытого контура: аудио, транскрипт и протокол остаются на компьютере пользователя.

### Проверка транскрибации без интерфейса

```bat
py -c "from app.transcription import transcribe_audio, segments_to_text; print(segments_to_text(transcribe_audio('meeting.mp3', 'small')))"
```

По умолчанию включён локальный акустический fallback: голосовые признаки
сегментов кластеризуются в локальные дорожки и получают метки `SPEAKER_00/01`.
Для полноценной акустической
диаризации можно отдельно установить `pyannote.audio`, скачать checkpoint в
локальный кэш и задать `HF_TOKEN` только для доступа к checkpoint. Аудиофайл
при этом остаётся локальным; если pyannote не настроен, приложение продолжает
работать на fallback без облачных API.

## Ограничения текущего MVP

Акустический fallback является эвристикой и не распознаёт личность человека;
для длинных реплик или близких тембров возможны ошибки. Для демо с реальными разными голосами рекомендуется подключить
локальную модель pyannote; имена участников всё равно нужно сопоставить с
`SPEAKER_00`, `SPEAKER_01` вручную или через голосовые профили.

Если в реплике есть обращение вроде «Гульмира Сериковна, вам слово» или
«Нурлан Сагатович, какая ситуация?», следующая реплика получает имя из
обращения. Это текстовая подсказка, а не подтверждение личности по голосу;
при отсутствии обращения остаётся акустическая метка `SPEAKER_XX`.

Для памяти голосов используется локальный ECAPA-модуль SpeechBrain. Он
отключён по умолчанию, чтобы не замедлять обычную транскрибацию. Для включения
установите `speechbrain` и задайте `ENABLE_VOICE_PROFILES=1`. После
первого именного обращения профиль сохраняется в `data/voice_profiles.json`,
а на следующих запусках новые реплики сравниваются с ним по голосовому
embedding. Файл с профилями хранится только локально и не добавляется в Git.
Если SpeechBrain не установлен, система не делает рискованных догадок по
спектру и использует обычные `SPEAKER_XX`/именные текстовые подсказки.
